# Хаб Коллекционера — сервис переноса коллекций

Учебный проект по дисциплине «Методы и средства проектирования информационных систем». Текущая версия исходников — 0.1.0. Сервис принимает CSV, XLSX, JSON и структурированный TXT, показывает соответствие полей и создаёт ZIP для DomCollection.

## Что уже работает

- Чтение таблиц CSV/XLSX, списков моделей JSON и текстовых списков вида `A01 Название — описание` или Telegram-списков (в том числе вставленных на странице).
- Просмотр столбцов и всех записей до конвертации с подтверждением проверки. Категория означает тип предмета, бренд хранится отдельно, год выпуска и явно указанные признаки попадают в теги. Масштаб `1:64` для автомобилей можно выбрать при переносе.
- Адаптивные страницы в светлой и тёмной темах с цветами и шрифтами мобильного приложения.
- Страница `/order` по секретному коду: статус, загрузка файла/текста в оплаченный заказ, согласия/CAPTCHA, ход работы, остановка, просмотр/исправления моделей со сверкой строк, ZIP и отдельное подтверждение сохранения. Выдача кодов и оплата ещё не подключены; обычный посетитель пока не получает оплаченный заказ. Инструкция — [GUEST_ORDER_TRANSFER.md](docs/GUEST_ORDER_TRANSFER.md), ручные сценарии O/P — в общем списке.
- Перевод цены покупки из EUR в RUB по [официальному курсу Банка России](https://www.cbr.ru/development/sxml/) с указанием даты курса в заметках.
- Загрузка личных фотографий Hunt64 по ссылкам из столбца `My Photo URL`, преобразование WebP/PNG/JPG в JPG.
- Заглушка для отсутствующего или недоступного фото. Дата переноса используется для записей без даты покупки и помечается в заметках.
- ZIP с `collection.json` и `photos/*.jpg` по формату импорта мобильного приложения.
- Бесплатная инструкция `/guide` с готовым промптом для DeepSeek. Ответ можно вставить прямо на главной странице: сервис покажет все модели, потребует подтверждения проверки и сам создаст ZIP.
- Автоматический путь `/automatic`: работает серверная проверка обязательных согласий и необязательного согласия на повторную передачу внешней нейросети. Имена владельцев и настройки ключей не выдаются гостю. Загрузка, ИИ, оплата и пример скачивания пока отключены; страница не принимает файлы и деньги.
- Cloudflare Turnstile перед сборкой ZIP и проверкой ИИ-условий: сервер проверяет токен, домен и назначение проверки. Без настройки или при отказе обработка закрыта. Условия обработки доступны на `/processing`.
- Вход администратора на `/admin/login` по коду из локальных настроек сервера. После входа действует серверная сессия с кнопкой выхода; страницы панели и API управления ключами закрыты для гостей. Ключи шифруются на диске; в интерфейсе видны только последние четыре символа. Кнопка «Проверить» запрашивает состояние ключа в OpenRouter.
- Пробное распознавание свободного текста через бесплатную `nvidia/nemotron-3-super-120b-a12b:free`: администратор выбирает основной включённый ключ, получает список до 100 моделей и передаёт его на полный предпросмотр перед ZIP. Фоновые задания используют ту же модель. При отдельном согласии для конкретного запроса сервис может использовать до двух резервных ключей других владельцев при ограничении частоты или приближении к локальному порогу. Цена и валюта требуют проверки человеком. Доступность бесплатного API проверяется отдельно на действующем ключе.
- Фоновые ИИ-задания в закрытой админ-панели: файл или текст разбивается на части, показывается прогресс, доступна отмена и восстановление списка после обновления страницы. Каждая исходная строка должна быть связана с моделью или показана в сверке без модели; пропуск без объяснения отклоняет часть. Повтор запроса с тем же номером и исходником возвращает то же задание, пока его запись находится в памяти. Проверенные модели передаются в существующий предпросмотр и сборку ZIP с CAPTCHA.

Свободный текст и сообщения Telegram можно разобрать вручную через DeepSeek по инструкции `/guide`. Автоматическое распознавание доступно администратору и по уже оплаченному заказу в закрытом пилоте; оформление, платежи и выдача гостевых кодов ещё не реализованы. Фото с произвольных сайтов и входные ZIP не поддерживаются. Архив добавляет модели в приложении; автоматического поиска дублей при импорте нет. Лимиты одного переноса: 8 МБ входной файл, 300 моделей, 100 МБ выходной ZIP. Для OpenRouter: до 20 000 символов и 100 моделей за запрос. На один адрес действуют лимиты 30 предпросмотров и 8 сборок ZIP в минуту; одновременно сервер собирает не более двух архивов.

## Обработка файлов

Пользовательские исходники, фотографии и ZIP обрабатываются в оперативной памяти и не записываются на диск. Фоновые ИИ-задания также хранятся только в RAM: максимум три задания, один ИИ-запрос одновременно, до 15 минут ожидания/обработки и 10 минут доступа к результату. Административный результат освобождается после передачи в предпросмотр; внутренний результат заказа — после подтверждения сохранения ZIP. Ошибка, отмена и срок очищают содержимое; операция удерживает рабочий слот до фактической остановки. Все сборки ZIP делят два места и срок две минуты; при отключении браузера сборка останавливается. После перезапуска потребуется повторная загрузка. Настройки администратора и зашифрованные API-ключи сохраняются отдельно. Подробности — в [инструкции фоновых заданий](docs/BACKGROUND_JOBS.md), [выдаче заказа](docs/ORDER_DELIVERY.md) и [плане сервиса](docs/PUBLIC_SERVICE_ROADMAP.md).

## Разработка и проверка

В админке доступен раздел «Заказы»: неоплаченные черновики на 149 ₽ сохраняются после перезапуска. Коллекции в них не записываются. Серверная основа проверяет повторные запросы, состояния оплаты и попыток. Внутренние адаптеры связывают оплаченный заказ с очередью ИИ, проверкой моделей, ZIP и отдельным подтверждением его сохранения. Повтор разрешён после остановки работы и записи статуса. `/order` проверяет статус по коду, передаваемому телом запроса; для операций переноса код передаётся заголовком до чтения загрузки. Сайт не сохраняет код в браузере. Платёжный сервис, выдача кодов и гостевые исправления/ZIP ещё не подключены. Инструкции — [учёт заказов](docs/ORDERS_AND_PAYMENTS.md), [гостевой перенос](docs/GUEST_ORDER_TRANSFER.md), [гостевой доступ](docs/GUEST_ORDER_ACCESS.md) и [проверка/ZIP](docs/ORDER_DELIVERY.md); ручные сценарии — разделы J–O. Хранилище рассчитано на один процесс сервиса.

В предпросмотре можно исправить отдельную модель кнопкой «Изменить». Данные проверяются в браузере и на сервере; черновики исчезают при обновлении страницы и не сохраняются в сервисе. Инструкция — [docs/MODEL_CORRECTIONS.md](docs/MODEL_CORRECTIONS.md), ручные сценарии — раздел I общего списка.

Инструкция для второго компьютера: [docs/SECOND_COMPUTER_SETUP.md](docs/SECOND_COMPUTER_SETUP.md).
Настройка CAPTCHA: [docs/CAPTCHA_SETUP.md](docs/CAPTCHA_SETUP.md). Накопительный список ручных проверок: [docs/MANUAL_TEST_CHECKLIST.md](docs/MANUAL_TEST_CHECKLIST.md).

```sh
npm ci
npm test
npm start
```

Откройте `http://localhost:8080`. Для Docker на Windows запустите `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-docker.ps1`, на Linux и macOS — `sh ./scripts/start-docker.sh`. Скрипт соберёт образ для архитектуры текущего компьютера, один раз создаст локальный `.env` и покажет админ-код. Подробности — в [инструкции](docs/SECOND_COMPUTER_SETUP.md).

Образ `semiys/mispisit-lab1:0.0.1` в Docker Hub относится к первой лабораторной и содержит только исходную страницу. Новая версия сервиса в Docker Hub пока не опубликована.
