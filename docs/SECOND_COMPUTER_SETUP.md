# Запуск сервиса на втором компьютере

Сервис можно проверять двумя способами. Выберите **один**; ставить и Docker, и Node.js не требуется. Если Docker уже работает в виртуальной машине с Windows 11, используйте первый вариант.

## Вариант A — Docker на Windows, Linux или macOS

Нужно:

1. Работающий Docker: на Windows и macOS — Docker Desktop с Linux-контейнерами, на Linux — Docker Engine или Docker Desktop. В вашей виртуальной машине Windows 11 Docker уже запускался — повторно устанавливать его не нужно.
2. Исходники репозитория `Semiys/collector-transfer-service` на компьютере, где выполняется Docker. Их можно получить через Git или скачать ZIP репозитория с GitHub.
3. Интернет для первой сборки образа, курса ЦБ и загрузки личных фото Hunt64.

На Windows в PowerShell из каталога репозитория выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-docker.ps1
```

На Linux или macOS в терминале из каталога репозитория выполните:

```sh
sh ./scripts/start-docker.sh
```

Оба скрипта собирают один Dockerfile и запускают одинаковый Linux-контейнер. При первом запуске скрипт создаст локальный `.env` с двумя случайными секретами и покажет **админ-код** в терминале. При следующих запусках он сохранит прежние секреты и данные. Откройте `http://localhost:8080` **в браузере той системы, где запущен Docker**. Админ-панель — `http://localhost:8080/admin`. Для остановки нажмите `Ctrl+C`; для следующего запуска повторите ту же команду. Если Docker работает внутри виртуальной машины, для открытия сервиса с компьютера-хоста потребуется отдельный проброс порта 8080 из виртуальной машины на хост. На Windows команда временно разрешает выполнение скрипта только для этого процесса и не меняет системную настройку PowerShell.

Образ собирается под архитектуру компьютера, где выполняется `docker build`. В текущем Dockerfile базовый Node.js-образ и зависимость обработки фото доступны для `linux/amd64` и `linux/arm64`; это покрывает типичные ПК и Mac с Apple Silicon. Если позже публиковать **один тег готового образа** для обеих архитектур в Docker Hub, его нужно отдельно собрать и проверить как multi-platform образ. Старый тег `semiys/mispisit-lab1:0.0.1` относится только к ЛР1.

## Вариант B — запуск без Docker

Нужно:

1. Node.js версии 24 с npm (npm входит в установщик Node.js).
2. Исходники репозитория через Git или ZIP.
3. Интернет при установке зависимостей, для курса ЦБ и фото Hunt64.

В каталоге репозитория:

```sh
npm ci
npm test
npm start
```

На Windows PowerShell, если команда `npm` заблокирована политикой выполнения, используйте `npm.cmd ci`, `npm.cmd test`, `npm.cmd start`. Затем откройте `http://localhost:8080`.

Если на Windows нужно сохранить место на диске C, **до** `npm.cmd ci` задайте кэш на диске D в этой сессии PowerShell:

```powershell
$env:npm_config_cache = 'D:\npm-cache'
npm.cmd ci
```

Это не меняет глобальные настройки npm. При запуске через Docker npm устанавливает зависимости внутри образа; место занимает хранилище Docker той виртуальной машины, где он запущен.

## Админ-панель API-ключей

Панель находится по адресу `http://localhost:8080/admin`. Она сохраняет список ключей, проверяет ключ по запросу через API OpenRouter и может распознать свободный текст через выбранный основной ключ. При отдельном согласии на конкретный запрос сервис может переключиться на ключи до двух других владельцев. Добавляйте API-ключи отдельных владельцев, которые дали согласие. Не вводите логины и пароли OpenRouter. Для регистрации и создания собственного ключа используйте [OpenRouter](https://openrouter.ai/sign-up) и [страницу ключей](https://openrouter.ai/keys).

При запуске через `scripts/start-docker.ps1` вручную создавать `.env` не нужно. Возьмите админ-код, показанный скриптом, и введите его на странице `/admin/login`. После входа откроется `/admin`; добавьте свой API-ключ OpenRouter через форму один раз — он сохранится после перезапуска контейнера. Сессия входа действует 12 часов или до нажатия «Выйти» и сбрасывается при перезапуске сервера; сам API-ключ повторно добавлять не требуется. После пяти неверных кодов вход с этого адреса блокируется на 15 минут. `.env` игнорируется Git; **не отправляйте его в чат и не добавляйте в репозиторий**. Сохраните резервную копию файла в надёжном месте: без ключа шифрования уже записанные API-ключи восстановить нельзя. Список ключей хранится в зашифрованном файле в постоянном Docker-томе `/app/data`.

Если запускаете сервис напрямую через Node.js, автоматический Docker-скрипт не используется: создайте `.env` с `ADMIN_ACCESS_TOKEN` и `OPENROUTER_KEY_ENC_KEY` (два разных случайных 64-значных шестнадцатеричных значения) и выполните `node --env-file=.env src/server.js`. При публичном размещении сначала настройте HTTPS и задайте `COOKIE_SECURE=true` в среде сервера, чтобы браузер отправлял админ-сессию только по HTTPS.

Для теста ИИ войдите на `/admin/login`, выберите включённый основной ключ, вставьте текст коллекции и нажмите «Распознать текст». Если хотите разрешить резервные ключи, отметьте отдельную галочку с именами их владельцев перед каждым запросом. При ответе 429 или приближении к локальному порогу сервис может выбрать резервный ключ; галочка сбрасывается после запроса. Текст отправляется через OpenRouter выбранной бесплатной модели; уберите из него личные данные до отправки. После ответа нажмите «Проверить модели и подготовить ZIP»: откроется обычный экран переноса со всеми распознанными строками. Проверьте данные и валюту цены, подтвердите замечания, затем скачайте ZIP. Для публичных пользователей этот маршрут пока закрыт серверной сессией. Локальный счётчик не знает точного остатка лимита OpenRouter и сбрасывается при перезапуске сервера.

## Фоновые задания администратора

Для нового фонового режима после пересборки контейнера откройте блок **«Перенести файл с помощью ИИ»** в админ-панели. Новые настройки `.env` или программы не нужны. Порядок проверки — [BACKGROUND_JOBS.md](BACKGROUND_JOBS.md); ручные сценарии — раздел H в [MANUAL_TEST_CHECKLIST.md](MANUAL_TEST_CHECKLIST.md). Этот режим принимает файл или длинный текст, показывает прогресс и сверку. Он остаётся закрытым для гостей. Ограничения пилота — до 300 непустых исходных записей и 200 000 символов, три задания в RAM, один запрос ИИ одновременно.

## Что устанавливать не нужно

Для проверки заказов новые программы не нужны. После пересборки откройте в админке **«Заказы»**. Можно создать неоплаченный черновик на 149 ₽ и проверить его сохранение после перезапуска. В существующем томе `/app/data` появился `orders.json` — только служебные номера, суммы, хеши доступа и статусы, без коллекций. Подробности — [ORDERS_AND_PAYMENTS.md](ORDERS_AND_PAYMENTS.md), ручные проверки — раздел J. Реальные платежи и гостевые оплаченные задания ещё не подключены. Для этой версии запускайте один экземпляр контейнера сервиса; общий том между несколькими экземплярами не поддерживается.

Для обычного переноса файлов не нужны Android Studio, JDK, Gradle, база данных, платный ИИ или ключи OpenRouter. Для пробного распознавания свободного текста нужен API-ключ OpenRouter. Библиотеки из `package.json` устанавливаются **внутри каталога проекта** командой `npm ci` либо **внутри Docker-образа** командой `docker build`.

## Проверка

### Автоматические тесты через Docker без установки Node.js в Windows

Сначала собрать и запустить актуальный образ скриптом `scripts/start-docker.ps1`. Затем открыть **второе окно PowerShell** в каталоге репозитория:

```powershell
$testPath = (Resolve-Path .\test).Path
docker run --rm --mount "type=bind,source=$testPath,target=/app/test,readonly" collector-transfer-service:0.1.0 npm test
```

Папка `test` подключается только для этого запуска и только для чтения: в обычный образ приложения она не копируется. Без подключения папки команда может найти ноль тестов. Ожидается `tests 97`, `pass 97`, `fail 0`; подставные ответы внешних API и вымышленные платежи не расходуют лимиты настоящего ключа и не списывают деньги. Запуск самого Docker на втором ПК ещё нужно проверить пользователю; на основном ПК проверен комплект Node.js-тестов.

Для логов найти контейнер сервиса в `docker ps`, скопировать его ID и выполнить `docker logs <ID>`. В журнале не должно быть коллекций или API-ключей. Для остановки основного сервера нажать `Ctrl+C` в первом окне PowerShell. Исходники и зашифрованные ключи сохраняются; задания в RAM исчезают.

Локальные 97 проверок выполнены на уже установленном Node.js 22.14.0. Целевая версия сервиса и образа — Node.js 24; приведённый запуск тестов внутри Docker проверит именно её. Это отдельная проверка на втором ПК. Внутренние адаптеры оплаченного заказа к очереди/ZIP проверяются автоматически; публичных платных действий ещё нет. Сценарии на будущее — разделы K и M.

Сборка ZIP теперь имеет срок две минуты и общий лимит двух архивов для бесплатного пути и внутренних заказов. Отмена соединения останавливает работу; место освобождается после фактического выхода. Для бесплатного пути вручную проверьте обычное скачивание и повтор после отмены (раздел N); трудные случаи обрыва/срока дополнительно проверяет `test/archive-capacity.test.js`. Подробности внутреннего оплаченного пути — [ORDER_DELIVERY.md](ORDER_DELIVERY.md).

Страница `/order` и кнопка «Проверить заказ» на `/automatic` добавлены. Пока выдачи гостевых кодов нет, вручную доступны проверки состояния страницы, неверного кода, очистки, двух тем и мобильного размера. Успешный доступ и перезапуск проверяет `test/guest-orders.test.js` на отдельном вымышленном заказе. Админ-код, номер черновика и хеш из `orders.json` не заменяют код доступа. Инструкция — [GUEST_ORDER_ACCESS.md](GUEST_ORDER_ACCESS.md), ручные сценарии — раздел L.

Перед скачиванием ZIP настройте Cloudflare Turnstile по [CAPTCHA_SETUP.md](CAPTCHA_SETUP.md). Для локальной проверки можно использовать официальные тестовые ключи с явным тестовым режимом. Без CAPTCHA предпросмотр работает, но сервер не создаёт архив. Накопительный список фич и сценариев проверки: [MANUAL_TEST_CHECKLIST.md](MANUAL_TEST_CHECKLIST.md).

Загрузите CSV Hunt64 или тестовую XLSX/JSON, проверьте столбцы, курс ЦБ для EUR и скачайте ZIP. Бесплатный ручной сценарий для пользователей размещён на странице `/guide`: скопируйте промпт, получите JSON в DeepSeek, вставьте его на главной странице и скачайте ZIP после проверки. При недоступной ссылке Hunt64 сервис подставит заглушку и покажет номера строк. Импортируйте ZIP в DomCollection на тестовом телефоне. Повторный импорт добавляет те же модели ещё раз.

Текущие ограничения: до 8 МБ входного файла, до 300 моделей и до 100 МБ ZIP за один перенос. На один IP-адрес допускается до 30 предпросмотров и 8 сборок ZIP в минуту, одновременно собираются не более двух архивов. Эти счётчики находятся в памяти сервера и сбрасываются при перезапуске. ИИ обрабатывает до 20 000 символов и 100 моделей за запрос; реальные ответы OpenRouter нужно проверить с вашим ключом. Фото из произвольных сайтов и входные ZIP пока не обрабатываются.
