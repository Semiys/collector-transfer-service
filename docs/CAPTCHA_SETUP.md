# Настройка CAPTCHA на втором компьютере

Используется Cloudflare Turnstile. Установка программ или новых npm-библиотек для этой интеграции не нужна. В браузер передаётся только публичный site key; secret key остаётся на сервере. CAPTCHA проверяется сервером перед сборкой ZIP, а на странице `/automatic` — при проверке согласий. Подробности: [проверка токена](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/), [официальные тестовые ключи](https://developers.cloudflare.com/turnstile/troubleshooting/testing/).

Без настроенных ключей и допустимых доменов предпросмотр остаётся доступен, но сборка ZIP и проверка автоматического пути закрыты. Нельзя просто скрыть виджет и пропустить проверку на сервере.

## 0. Где зарегистрироваться и что потребуется

Настройку выполняйте на втором ПК, **в Windows 11 виртуальной машины**, где работает Docker. Репозиторий должен быть обновлён через GitHub Desktop → Fetch origin → Pull origin. Первый запуск описан в [SECOND_COMPUTER_SETUP.md](SECOND_COMPUTER_SETUP.md).

1. Откройте [Cloudflare Dashboard](https://dash.cloudflare.com/). Если аккаунта нет, нажмите **Sign up**, зарегистрируйтесь с доступным вам адресом электронной почты и подтвердите почту, если сервис попросит. Если аккаунт есть — войдите в него.
2. В панели выберите ваш аккаунт, найдите **Turnstile** через меню или поиск. Нужен именно Turnstile, а не API Token всего аккаунта Cloudflare.
3. Не нужно переносить домен или менять DNS ради локальной CAPTCHA. Для проверки на компьютере создайте отдельный виджет для разработки. Позднее для публичного сайта создайте второй виджет с настоящим доменом.
4. Имена настроек ниже относятся к нашему проекту. Публичный **Site key** попадёт в браузер; **Secret key** используется только сервером для проверки результата.

Порядок создания виджета: [официальная инструкция Cloudflare](https://developers.cloudflare.com/turnstile/get-started/widget-management/dashboard/). Cloudflare разрешает явно добавить `localhost` и `127.0.0.1` в список допустимых адресов, но не рекомендует такие адреса для рабочего публичного виджета: [локальная разработка](https://developers.cloudflare.com/turnstile/troubleshooting/testing/).

## Настоящая CAPTCHA на локальном Docker — рекомендуемый следующий шаг

### Создать виджет

1. В **Turnstile** нажмите **Add widget**.
2. **Widget name**: например, `Collector Transfer — local`.
3. В **Hostname management** добавьте отдельно `localhost` и `127.0.0.1`. Пишите только имя: без `http://`, без `:8080` и без `/admin`. Эти адреса нужны для открытия сайта **в браузере той же виртуальной машины**.
4. **Widget mode**: **Managed**. Проверка сама решает, нужна ли галочка пользователю; видимая CAPTCHA не обязана спрашивать её при каждом заходе.
5. Если предлагается **Pre-clearance**, оставьте выключенным: наш сервер проверяет токен напрямую.
6. Нажмите **Create**. Оставьте страницу с **Site key** и **Secret key** открытой, пока переносите их в настройки. Не отправляйте секрет, пароль или снимок секретов в чат.

### Внести ключи в `.env`

1. На втором ПК откройте папку репозитория. Это та папка, в которой лежат `Dockerfile`, `package.json` и `scripts`. Откройте в ней PowerShell.
2. Если контейнер работает в терминале, остановите его **Ctrl+C**. Если `.env` ещё нет, сначала выполните `scripts/start-docker.ps1` по инструкции первого запуска, дождитесь создания `.env`, затем остановите контейнер.
3. Откройте файл:

   ```powershell
   notepad .env
   ```

4. **Сохраните существующие `ADMIN_ACCESS_TOKEN` и `AI_KEY_ENC_KEY`** (либо прежний `OPENROUTER_KEY_ENC_KEY`). Они нужны для входа и расшифровки сохранённых ключей. Не создавайте их заново и не копируйте чужие значения.
5. Замените тестовые настройки CAPTCHA следующим блоком. Вместо текста после двух знаков `=` вставьте соответствующие ключи Cloudflare **целиком**:

   ```dotenv
   NODE_ENV=production
   TURNSTILE_TEST_MODE=false
   TURNSTILE_TEST_DOCKER_LOCAL=false
   TURNSTILE_SITE_KEY=ВСТАВЬТЕ_SITE_KEY
   TURNSTILE_SECRET_KEY=ВСТАВЬТЕ_SECRET_KEY
   TURNSTILE_HOSTNAMES=localhost,127.0.0.1
   ```

6. Каждая переменная должна быть указана ровно один раз. Уберите старые строки с тестовыми ключами; не добавляйте пробелы вокруг `=`, кавычки, угловые скобки или слово `Bearer`. Не заменяйте весь файл этим блоком: строки администратора должны остаться.
7. Сохраните как `.env` в UTF-8. Проверьте в Проводнике с включённым отображением расширений, что файл не стал `.env.txt`. Используется **`.env`**, не `.env.example`. `.env` уже исключён из Git, его не коммитить.

### Запустить и проверить

1. В PowerShell из папки репозитория выполните:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-docker.ps1
   ```

2. Дождитесь запуска и оставьте терминал открытым. Скрипт читает `.env` при создании нового контейнера: одного обновления страницы после изменения файла недостаточно.
3. В браузере виртуальной машины откройте `http://localhost:8080/api/captcha/config`. Ожидается `configured: true`, ваш публичный `siteKey` и `testMode: false`. Secret key здесь не показывается. Если виден прежний тестовый ключ, запущен старый контейнер либо изменён файл в другой папке.
4. Откройте `http://localhost:8080`, выберите небольшой тестовый файл и дойдите до предпросмотра. Внизу должна появиться проверка человека. При **Managed** она может пройти автоматически — это нормальная работа.
5. Подтвердите предпросмотр и замечания, скачайте ZIP. Успех виджета проверяется сервером; одна зелёная галочка ещё не подтверждает правильность secret key.
6. Нажмите «Повторить проверку» и повторите сборку со свежим токеном. Отдельно проверьте страницу `/automatic` и сценарий заказа, если он доступен в вашей тестовой конфигурации. Оплата в сервисе пока не подключена.

Скрипт локального запуска задаёт Docker-флаг тестового транспорта; при `TURNSTILE_TEST_MODE=false` он не ослабляет настоящую CAPTCHA. Порт остаётся доступен только локально. Для запуска с телефона или для публичного сайта нужен отдельный адрес, разрешённый в настройках виджета и сервера.

### Если проверка не появилась

- `configured: false` — проверьте обе строки ключей, `TURNSTILE_HOSTNAMES`, отсутствие дубликатов и пересоздание контейнера.
- `configured: true`, но «не загрузилась» — браузер должен иметь доступ к `challenges.cloudflare.com`. Проверьте блокировщик, фильтрацию сети и интернет. Настоящие ключи сами по себе не исправляют блокировку загрузки скрипта. В загрузчике срок 15 секунд включает ожидание готовности API; бесконечного ожидания этой фазы быть не должно.
- Есть сообщение с **кодом CAPTCHA** — пришлите только его и адрес страницы без секретов; код поможет отличить запрещённый hostname от проблем браузера.
- Виджет прошёл, но сервер отказал — проверьте secret key из **того же виджета**, hostname и доступ контейнера к Cloudflare. Не подставляйте тестовый secret key к настоящему site key.

## Другие аккаунты сервиса

Для ИИ уже используется Groq. Регистрация, создание ключа и его проверка описаны пошагово в [GROQ_SETUP.md](GROQ_SETUP.md). **Groq API-ключ добавляйте через закрытую админ-панель**, а не в HTML, `.env.example` или чат. `.env` нужен для серверных настроек CAPTCHA, входа администратора и шифрования ключей. Если Groq уже подключён, повторная регистрация не нужна. Регистрация в OpenRouter для текущего сервиса не требуется.

Платёжный сервис пока не выбран: дополнительные платёжные аккаунты и ключи на этом этапе не нужны.

## 1. Сначала проверить локально

1. Запустите Docker по [SECOND_COMPUTER_SETUP.md](SECOND_COMPUTER_SETUP.md), чтобы скрипт создал ваш `.env` с админ-кодом и ключом шифрования.
2. Остановите контейнер через `Ctrl+C`.
3. Откройте `.env` в редакторе. Сохраните обе существующие строки администратора. Добавьте следующие строки **только для локального теста**:

```dotenv
NODE_ENV=development
TURNSTILE_SITE_KEY=1x00000000000000000000AA
TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA
TURNSTILE_HOSTNAMES=localhost,127.0.0.1
TURNSTILE_TEST_MODE=true
```

4. Если эти параметры уже есть, замените их значения; не оставляйте дубли одинаковых переменных. Сохраните `.env` в UTF-8.
5. Повторите запуск актуального Docker-скрипта. В Windows PowerShell из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-docker.ps1
```

   Скрипт пересоберёт образ и передаст настройки из `.env`. Он публикует порт только на `127.0.0.1` и задаёт `TURNSTILE_TEST_DOCKER_LOCAL=true`: в явном локальном тестовом режиме сервер допускает частный транспортный IP, который Docker может подставить вместо loopback. На Linux/macOS используется `sh ./scripts/start-docker.sh`. При запуске без Docker используйте `node --env-file=.env src/server.js`, а не обычный `npm start`, который сам `.env` не читает.
6. Откройте `http://localhost:8080` **в браузере виртуальной машины**. Выберите файл, проверьте предпросмотр и подтверждения. Тестовый виджет должен пройти проверку автоматически и показать пометку о локальном тестовом режиме. Скачайте ZIP.
7. Для `/automatic` сначала добавьте свой Groq-ключ через защищённую админ-панель. На этой странице пока работает только проверка согласий и CAPTCHA; файл не загружается, запрос к ИИ не выполняется, деньги не списываются.

Эти ключи опубликованы Cloudflare для тестирования и всегда дают заранее заданный результат. Они **не защищают публичный сайт от ботов**. Наш сервер допускает их только при явном тестовом режиме, вне `NODE_ENV=production` и для локального имени хоста. Без Docker-флага нужен loopback-IP; с флагом допускаются также частные IPv4-адреса транспорта (10/8, 172.16/12, 192.168/16), включая IPv4-mapped IPv6. Флаг предназначен только для локального контейнера с портом на `127.0.0.1`; не включать его при публикации в сеть. Токен всё равно проверяется через Cloudflare Siteverify. Если открыть сайт с телефона по LAN-адресу компьютера, тестовый режим будет отклонён. Для такой проверки нужны реальные ключи и разрешённый домен.

Если остаётся «Загружаю проверку человека…», откройте `http://localhost:8080/api/captcha/config`: должны быть `configured: true` и `testMode: true`. При `false` проверьте `.env`, отсутствие дублирующихся настроек и перезапуск контейнера. Если настройки верны, подождите до 15 секунд, нажмите «Повторить проверку» и проверьте доступ браузера/контейнера к `challenges.cloudflare.com`: тестовые ключи тоже требуют интернет. Не присылайте secret key или содержимое `.env`.

Для проверки отказа замените только `TURNSTILE_SECRET_KEY` на официальный тестовый ключ `2x0000000000000000000000000000000AA`, перезапустите сервер и попробуйте скачать ZIP: сервер должен отказать. Затем верните успешный тестовый ключ.

## 2. Реальные ключи перед публичным запуском

1. Войдите в [Cloudflare Dashboard](https://dash.cloudflare.com/). Откройте раздел **Turnstile** и создание виджета (**Add widget**).
2. Укажите название, например `Collector Transfer`, и домен будущего сайта. Домены задаются без `https://`, пути и порта. Выберите режим **Managed** и создайте виджет.
3. Скопируйте **site key** и **secret key** в `.env` на компьютере/сервере, где запускается контейнер:

```dotenv
NODE_ENV=production
TURNSTILE_TEST_MODE=false
TURNSTILE_TEST_DOCKER_LOCAL=false
TURNSTILE_SITE_KEY=ВАШ_ПУБЛИЧНЫЙ_SITE_KEY
TURNSTILE_SECRET_KEY=ВАШ_СЕКРЕТНЫЙ_SECRET_KEY
TURNSTILE_HOSTNAMES=ваш-домен.example
```

4. Замените примеры настоящими значениями. В `TURNSTILE_HOSTNAMES` перечислите только ваши домены, разрешённые и в Cloudflare. Перезапустите контейнер.
5. При публикации настройте HTTPS и `COOKIE_SECURE=true` для админ-сессии. Если используется reverse proxy, укажите в `TRUST_PROXY` только фактические доверенные IP-адреса или CIDR этого прокси. Без прокси оставьте переменную пустой. Не задавайте доверие всем адресам.
6. Проверьте весь сценарий с реальными ключами и доменом по [ручному списку](MANUAL_TEST_CHECKLIST.md).

`.env` игнорируется Git. Секрет CAPTCHA и Groq-ключи нельзя помещать в HTML/JS или присылать в чат. `.env.example` — справочник доступных переменных без секретов.

## Что проверяет сервер

- Наличие и длину токена, ответ Cloudflare, домен и назначение проверки: создание ZIP либо проверка ИИ-условий.
- При отказе, истечении токена или недоступности Cloudflare обработка не начинается.
- После попытки интерфейс сбрасывает токен; повтор требует свежей проверки. В рабочем режиме повторное использование токена отклоняет Siteverify.
- Исходные файлы в Cloudflare не отправляются: сервер передаёт только токен, IP-адрес и свой секрет проверки.
- Лимиты размера файлов, количества запросов и параллельных сборок остаются обязательными вместе с CAPTCHA.
