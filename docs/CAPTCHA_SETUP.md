# Настройка CAPTCHA на втором компьютере

Используется Cloudflare Turnstile. Установка программ или новых npm-библиотек для этой интеграции не нужна. В браузер передаётся только публичный site key; secret key остаётся на сервере. CAPTCHA проверяется сервером перед сборкой ZIP, а на странице `/automatic` — при проверке согласий. Подробности: [проверка токена](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/), [официальные тестовые ключи](https://developers.cloudflare.com/turnstile/troubleshooting/testing/).

Без настроенных ключей и допустимых доменов предпросмотр остаётся доступен, но сборка ZIP и проверка автоматического пути закрыты. Нельзя просто скрыть виджет и пропустить проверку на сервере.

## 1. Сначала проверить локально

1. Запустите Docker по [SECOND_COMPUTER_SETUP.md](SECOND_COMPUTER_SETUP.md), чтобы скрипт создал ваш `.env` с админ-кодом и ключом шифрования.
2. Остановите контейнер через `Ctrl+C`.
3. Откройте `.env` в редакторе. Сохраните обе существующие строки администратора. Добавьте следующие строки **только для локального теста**:

```dotenv
NODE_ENV=development
TURNSTILE_SITE_KEY=1x00000000000000000000AA
TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA
TURNSTILE_HOSTNAMES=localhost,127.0.0.1
TURNSTILE_TEST_MODE=true
```

4. Если эти параметры уже есть, замените их значения; не оставляйте дубли одинаковых переменных. Сохраните `.env` в UTF-8.
5. Повторите запуск Docker-скрипта. Переменные из `.env` попадут в контейнер. При запуске без Docker используйте `node --env-file=.env src/server.js`, а не обычный `npm start`, который сам `.env` не читает.
6. Откройте `http://localhost:8080` **в браузере виртуальной машины**. Выберите файл, проверьте предпросмотр и подтверждения. Тестовый виджет должен пройти проверку автоматически и показать пометку о локальном тестовом режиме. Скачайте ZIP.
7. Для `/automatic` сначала добавьте свой OpenRouter-ключ через защищённую админ-панель. На этой странице пока работает только проверка согласий и CAPTCHA; файл не загружается, запрос к ИИ не выполняется, деньги не списываются.

Эти ключи опубликованы Cloudflare для тестирования и всегда дают заранее заданный результат. Они **не защищают публичный сайт от ботов**. Наш сервер допускает их только при явном тестовом режиме, вне `NODE_ENV=production`, для локального домена и IP-адреса. Если открыть сайт с телефона по LAN-адресу компьютера, тестовый режим будет отклонён. Для такой проверки нужны реальные ключи и разрешённый домен.

Для проверки отказа замените только `TURNSTILE_SECRET_KEY` на официальный тестовый ключ `2x0000000000000000000000000000000AA`, перезапустите сервер и попробуйте скачать ZIP: сервер должен отказать. Затем верните успешный тестовый ключ.

## 2. Реальные ключи перед публичным запуском

1. Войдите в [Cloudflare Dashboard](https://dash.cloudflare.com/). Откройте раздел **Turnstile** и создание виджета (**Add widget**).
2. Укажите название, например `Collector Transfer`, и домен будущего сайта. Домены задаются без `https://`, пути и порта. Выберите режим **Managed** и создайте виджет.
3. Скопируйте **site key** и **secret key** в `.env` на компьютере/сервере, где запускается контейнер:

```dotenv
NODE_ENV=production
TURNSTILE_TEST_MODE=false
TURNSTILE_SITE_KEY=ВАШ_ПУБЛИЧНЫЙ_SITE_KEY
TURNSTILE_SECRET_KEY=ВАШ_СЕКРЕТНЫЙ_SECRET_KEY
TURNSTILE_HOSTNAMES=ваш-домен.example
```

4. Замените примеры настоящими значениями. В `TURNSTILE_HOSTNAMES` перечислите только ваши домены, разрешённые и в Cloudflare. Перезапустите контейнер.
5. При публикации настройте HTTPS и `COOKIE_SECURE=true` для админ-сессии. Если используется reverse proxy, укажите в `TRUST_PROXY` только фактические доверенные IP-адреса или CIDR этого прокси. Без прокси оставьте переменную пустой. Не задавайте доверие всем адресам.
6. Проверьте весь сценарий с реальными ключами и доменом по [ручному списку](MANUAL_TEST_CHECKLIST.md).

`.env` игнорируется Git. Секрет CAPTCHA и OpenRouter-ключи нельзя помещать в HTML/JS или присылать в чат. `.env.example` — справочник доступных переменных без секретов.

## Что проверяет сервер

- Наличие и длину токена, ответ Cloudflare, домен и назначение проверки: создание ZIP либо проверка ИИ-условий.
- При отказе, истечении токена или недоступности Cloudflare обработка не начинается.
- После попытки интерфейс сбрасывает токен; повтор требует свежей проверки. В рабочем режиме повторное использование токена отклоняет Siteverify.
- Исходные файлы в Cloudflare не отправляются: сервер передаёт только токен, IP-адрес и свой секрет проверки.
- Лимиты размера файлов, количества запросов и параллельных сборок остаются обязательными вместе с CAPTCHA.
