# Ручные проверки сервиса

Список накопительный: новые фичи добавляем сюда. Все пункты пока не отмечены — пользователь проверяет их на втором ПК. Автоматические проверки с подставными ответами внешних API не заменяют тест реального OpenRouter, CAPTCHA и Docker.

Последняя серверная проверка: 02.10.2026, полный комплект — 107/107 успешно на установленном Node.js 22.14.0. Добавлены загрузка и распознавание по уже оплаченному заказу, согласия/CAPTCHA, прогресс, отмена и просмотр моделей со сверкой. Использованы вымышленные платежи/результаты и подставные ИИ/CAPTCHA; реальных запросов нет. Гостевой предпросмотр проверен браузером в двух темах/320 px. Выдачи кодов, оплаты и гостевых исправлений/ZIP пока нет. Настоящие CAPTCHA, OpenRouter, платежи и Docker Node.js 24 остаются для второго ПК: эти проверки не подтверждают доступность модели, устранение внешнего 429 или полный платный путь.

## Подготовка

- Запустить актуальные исходники по [SECOND_COMPUTER_SETUP.md](SECOND_COMPUTER_SETUP.md), настроить CAPTCHA по [CAPTCHA_SETUP.md](CAPTCHA_SETUP.md).
- Взять маленькие тестовые коллекции без личных данных: CSV, XLSX, TXT и JSON; для проверки связей достаточно 3–5 моделей.
- Для OpenRouter добавить настоящий ключ через админ-панель. Оформление/оплата/выдача кодов ещё отключены; гостевые задания проверяются на отдельном тестовом оплаченном заказе, обычный черновик не подходит.

## A. Интерфейс и переходы — можно проверять сейчас

- [ ] A01. Главная, инструкция, вход, админ-панель, `/automatic` и `/processing` открываются без ошибок. Ссылки возвращают на нужную страницу.
- [ ] A02. На ПК блоки располагаются рядом; на ширинах 390 и 320 px складываются в одну колонку. Шапка, согласия, длинные имена владельцев и CAPTCHA не создают горизонтальную прокрутку.
- [ ] A03. Светлая и тёмная темы сохраняются после обновления страницы и переходов. Текст, кнопки и ошибки читаемы в обеих темах.
- [ ] A04. На телефоне предпросмотр моделей превращается в карточки с подписями полей; видны все записи, а не только первые пять.
- [ ] A05. Можно перейти к условиям обработки, затем вернуться. Текст объясняет обработку без сохранения файлов и отдельную передачу внешнему ИИ.
- [ ] A06. Основной гостевой интерфейс не описывает OpenRouter, API-ключи, лимиты аккаунтов или переключение ключей. Подробности внешней обработки доступны в раскрываемом разделе условий; согласие на отправку данных остаётся явным. Инструкция самостоятельного переноса сохраняет название DeepSeek, чтобы пользователь мог открыть нужный сервис.
- [ ] A07. Общая шапка ведёт к переносу, инструкции и условиям. Возврат на главную/к переносу оформлен кнопкой; активный раздел виден. Проверить обе темы на ПК и телефоне.
- [ ] A08. В форме выбран один способ: файл или текст. Для текста выбирается список либо JSON, видна соответствующая кнопка проверки. Смена источника сбрасывает старый предпросмотр и блокирует скачивание; повторное нажатие уже выбранного способа сохраняет текущий результат.
- [ ] A09. Кнопка «Вставить готовый ответ» в инструкции открывает форму текста с выбранным JSON и прокручивает к форме. Кнопка открытия DeepSeek ведёт на официальный чат в отдельной вкладке; копирование запроса работает.
- [ ] A10. Счётчик этапов отмечает добавление данных, проверку моделей и готовый ZIP по фактическому состоянию. Предпросмотр появляется после чтения источника; скачивание по-прежнему требует всех проверок и CAPTCHA. Блок соответствия столбцов можно раскрыть/свернуть.

## B. Бесплатный перенос — нужна настроенная CAPTCHA

- [ ] B01. CSV и XLSX: заголовки и число моделей определяются верно. Изменение соответствия столбцов меняет предпросмотр.
- [ ] B02. Структурированный TXT/Telegram: заголовки разделов не становятся моделями; коды, тире в названиях и порядок записей сохраняются.
- [ ] B03. Для пропущенных или неоднозначных строк показаны предупреждения. Без подтверждения предупреждений перенос не проходит.
- [ ] B04. JSON от DeepSeek: можно вставить массив или объект с `models`, в том числе из блока ```json. Все записи показаны; оборванный JSON отклонён с понятной ошибкой.
- [ ] B05. Без выбора столбца названия, валюты или подтверждения предпросмотра архив не скачивается. Можно исправить выбор и повторить.
- [ ] B06. Выбранный масштаб 1:64 подставляется только автомобилям без масштаба. Явный масштаб сохраняется, аксессуарам значение не подставляется.
- [ ] B07. Категория описывает тип предмета, бренд сохраняется отдельно. Год выпуска, Premium, MOC/Loose и исходные теги появляются в тегах импортированных моделей.
- [ ] B08. Цена EUR пересчитывается по показанному курсу ЦБ; исходная цена и курс есть в заметках. Оценочная стоимость не становится ценой покупки.
- [ ] B09. Нет даты покупки/цены/фото: используются дата переноса, 0 ₽ и заглушка с понятными пометками. Год выпуска и Date Added не превращаются в дату покупки.
- [ ] B10. Личное фото Hunt64 по доступной ссылке попадает в ZIP. PNG/WebP/JPG преобразуются в JPG. При недоступном фото создаётся заглушка и показаны номера строк.
- [ ] B11. ZIP содержит `collection.json` и `photos/*.jpg`. Импорт в DomCollection сохраняет число моделей, категории, теги, фотографии и цены без нарушения связей.
- [ ] B12. Несколько быстрых нажатий «Скачать ZIP» запускают одну текущую сборку. После ошибки кнопку можно использовать снова, пройдя новую CAPTCHA.
- [ ] B13. Неподдерживаемое расширение, повреждённый файл, файл больше 8 МБ и более 300 моделей дают понятную ошибку. После отказа маленький корректный файл работает.
- [ ] B14. После переноса на сервере нет копий исходника, фото или ZIP. В Docker-томе с настройками остаются только административные данные. Содержимое коллекции не выводится в журнал контейнера.

## C. CAPTCHA — сначала тестовые, затем реальные ключи

- [ ] C01. Без настроенных ключей предпросмотр работает, но ZIP не собирается. Видна причина, платёж/ИИ также не запускаются.
- [ ] C02. С официальными успешными тестовыми ключами на localhost проверка проходит и ZIP скачивается. Видна пометка о тестовом режиме.
- [ ] C03. С тестовым секретом отказа сервер запрещает сборку, даже если виджет показал успех. Можно вернуть настройки и повторить.
- [ ] C04. При недоступном интернете/Cloudflare отображается ошибка, ZIP не создаётся. После восстановления связи «Повторить проверку» позволяет продолжить.
- [ ] C05. Смена темы, истечение CAPTCHA или попытка сборки сбрасывает прежний токен. Для следующей попытки проходит новая проверка.
- [ ] C06. `NODE_ENV=production` вместе с тестовыми ключами не разрешает обработку. Для публичного домена работают только реальные ключи и правильный список доменов.
- [ ] C07. На реальном домене проверить рабочую CAPTCHA в настольном и мобильном браузерах, включая доступ из используемой сети. Истёкший или повторно отправленный токен отклоняется сервером.

## D. Условия автоматического пути — нужен хотя бы один ключ в админке

- [ ] D01. На `/automatic` показана доступность распознавания без технических объяснений и имён владельцев. Блока «Подробнее о передаче данных» нет. Без включённых ключей проверка условий недоступна.
- [ ] D02. Без обеих обязательных галочек и CAPTCHA кнопка «Проверить условия» недоступна.
- [ ] D03. При нескольких разных владельцах показана отдельная необязательная галочка на повторную передачу внешней нейросети, без имён и технической схемы ключей. Она не отмечена заранее. При одном участнике её нет.
- [ ] D04. Проверка проходит без согласия на резервные ключи. После попытки обязательные и необязательная галочки сбрасываются.
- [ ] D05. Открыть страницу в одном окне; в админке другого отключить/добавить ключ. Проверка старого списка должна предложить обновить и подтвердить сведения заново.
- [ ] D06. Во время проверки несколько нажатий не создают параллельные запросы. Успех явно сообщает: файл не отправлен, ИИ и оплата пока не запущены.
- [ ] D07. Загрузка файла, оплата 149 ₽ и скачивание демонстрационного результата остаются отключёнными. Пример моделей не подменяет реальную коллекцию.

## E. Администратор и ИИ — реальные ответы проверять отдельно

- [ ] E01. Гость по прямому `/admin` попадает на вход; административный API не отдаёт ключи без сессии. Бесплатный перенос не требует входа.
- [ ] E02. Правильный код открывает панель, неверный не открывает. Пять неверных попыток вызывают временную блокировку. Выход закрывает доступ и по старой вкладке.
- [ ] E03. Добавленный ключ хранится после перезапуска контейнера, в интерфейсе видны только последние символы. Выключение, проверка и удаление работают.
- [ ] E04. Qwen распознаёт реальный маленький TXT/Telegram-пример: сверить каждую модель, код, год, бренд, категорию, цену и теги. Не пропадают дубликаты, неизвестные значения не выдумываются.
- [ ] E05. Ошибка ключа, лимит OpenRouter, неверный JSON и обрыв ответа дают понятный отказ без выдачи повреждённого ZIP и раскрытия секретов.
- [ ] E06. Без согласия на переключение пробный запрос использует только основной ключ. С согласием при лимите использует только перечисленных резервных владельцев; в результате указан фактически использованный ключ.
- [ ] E07. Ответ ИИ можно передать на полный предпросмотр и затем собрать ZIP с новой CAPTCHA. Ничего не импортируется в телефон без проверки пользователем.
- [ ] E08. «Проверить» ключ показывает суточные числа «использовано / осталось / лимит», если API их предоставил. Без счётчика пишет, что остаток неизвестен; действительный ключ не обозначает доступность модели. Подробности — `OPENROUTER_LIMITS.md`.
- [ ] E09. Если реальный запрос получил 429, сообщение различает платформу/поставщика только при наличии сведений от API; иначе источник неизвестен. Указан срок от API либо пометка о местной паузе. Повтор внутри паузы показывает уменьшившееся время; в истории OpenRouter не появляется новая попытка к заблокированному ключу. Специально создавать много запросов для получения 429 не нужно.
- [ ] E10. В админке навигация «Ключи» раскрывает управление ключами. Короткая проба текста раскрывается отдельно; форма фонового переноса и список заданий доступны на основной странице. На 320 px кнопки шапки переносятся и не расширяют страницу.

## F. Запуск и ограничения

- [ ] F01. Docker-скрипт на Windows 11 VM запускает сайт. Повторный запуск сохраняет админ-код и ключи; `.env` не появляется в Git. Проверка Docker на Linux/macOS ещё отдельная, не считается пройденной автоматически.
- [ ] F02. Большое число запросов вызывает понятный ответ 429; занятые слоты сборки — 503 с возможностью повторить. После паузы корректный запрос проходит.
- [ ] F03. При публикации за прокси лимиты работают по настоящему IP посетителя; произвольный X-Forwarded-For не позволяет их обходить. Нужны правильно настроенные TRUST_PROXY и HTTPS.

## H. Фоновые ИИ-задания администратора — можно проверять сейчас

Инструкция: [BACKGROUND_JOBS.md](BACKGROUND_JOBS.md). Начать с тестовых 3–5 моделей; настоящий ключ добавляется через админ-панель. Все пункты ниже пользователь ещё проверяет самостоятельно.

- [ ] H01. Без входа `/admin` перенаправляет на вход, а API списка/результата заданий возвращает 401. После выхода ранее открытый результат нельзя получить с сервера.
- [ ] H02. CSV, XLSX, JSON, TXT и вставленный текст по отдельности создают задания. Файл вместе с текстом, пустой ввод, неподдерживаемый файл и отсутствие согласия не запускают ИИ. В XLSX учитывается первый заполненный лист с шапкой; встроенные фото не извлекаются.
- [ ] H03. Двойное быстрое нажатие «Создать задание» создаёт один номер. При кратковременной потере связи повторная отправка без изменения исходника возвращает тот же номер, пока запись задания в RAM. Изменённый исходник — отдельное новое задание.
- [ ] H04. На списке из 20–30 непустых строк прогресс меняется по частям, итоговый счётчик совпадает с результатом. Две одинаковые строки моделей остаются двумя моделями. Все исходные номера учтены; проверить вручную, что ИИ не назвал модель заголовком.
- [ ] H05. Добавить заголовок и неясную строку. В сверке видно исходный текст и причину отсутствия модели, а у моделей — исходные номера. Для TXT номера совпадают со строками файла; для таблиц это порядок непустых записей без шапки. До подтверждения сверки кнопка перехода отключена.
- [ ] H06. Обновить страницу во время обработки, затем снова войти при необходимости: тот же номер остаётся доступен. Закрыть и открыть вкладку до срока — результат ещё доступен. Перезапустить контейнер — задания исчезнут, понадобится повторная загрузка.
- [ ] H07. Создать два задания и отменить второе в очереди: оно не отправляется ИИ. Отменить первое во время обработки: следующие части не запускаются, результат недоступен. После фактической остановки можно создать новое задание.
- [ ] H08. Три задания/готовых результата занимают лимит. Четвёртое получает понятный отказ. Удалить готовый результат кнопкой — доступ к нему закрывается и место освобождается.
- [ ] H09. Готовый результат через 10 минут исчезает, открытая сверка очищается; переход к нему не работает. Ошибка не выдаёт частично разобранную коллекцию. При длительности вместе с очередью свыше 15 минут задание истекает. Последний сценарий может потребовать замедленного тестового ответа.
- [ ] H10. Без необязательного согласия текст идёт только через основной ключ. С согласием на перечисленных владельцев возможен резерв при 429/локальном пороге. В диагностике каждой части показан фактически использованный ключ. Отключение участника во время задания останавливает дальнейшие части и требует нового согласия.
- [ ] H11. Цена в EUR автоматически выбирает евро в предпросмотре, затем пересчитывается ЦБ. Для неизвестной валюты выбор пустой, скачивание без выбора запрещено. При разных/неподдерживаемых валютах цены пустые, исходные суммы сохранены в заметках; их нужно обработать вручную.
- [ ] H12. После подтверждения сверки открываются все модели в обычном предпросмотре. Серверный результат становится недоступен; для ZIP по-прежнему нужны подтверждения и CAPTCHA. Проверить импорт в DomCollection: названия, количество, категории, теги, цены, даты и фото-заглушки.
- [ ] H13. Файл больше 8 МБ, текст больше 200 000 символов, строка больше 8 000 или источник больше 300 непустых записей отклоняются с понятной ошибкой. Лимиты считаются по исходнику, а не только по количеству распознанных моделей.
- [ ] H14. В светлой/тёмной темах на ПК и телефоне читаемы прогресс, ошибки, длинные строки сверки и действия. Содержимое не выполняется как HTML; длинный текст не расширяет страницу по горизонтали.
- [ ] H15. После обработки/отмены в Docker-volume `collector-transfer-data` нет исходников, JSON результатов или ZIP; допустимы зашифрованные настройки ключей и служебный `orders.json` без коллекций. Найти ID контейнера через `docker ps`, затем проверить `docker logs <ID>`: там нет коллекций, API-ключей или ответов ИИ. Отсутствие файлов само по себе не доказывает очистку RAM: отмена, срок и недоступность результата проверяются отдельно.
- [ ] H16. Маленький файл на две модели при отказе API показывает номер части, 429 и паузу. Частичный ZIP и сверка моделей не выдаются. После паузы можно создать новое задание; исходный файл не сохранён для автоматического повтора.

## I. Исправление моделей перед ZIP — можно проверять сейчас

Инструкция: [MODEL_CORRECTIONS.md](MODEL_CORRECTIONS.md). Начать с маленького источника; для скачивания нужна CAPTCHA. Проверить применение правок на одном формате, затем открытие/сохранение для остальных: CSV, XLSX, TXT, JSON и вставленный текст/JSON.

- [ ] I01. У каждой модели есть «Изменить». Показаны девять полей, включая дополнительные исходные столбцы в заметках. Исправить поля и применить: новые значения в таблице, есть отметка «Исправлено».
- [ ] I02. В двух моделях с одинаковым названием изменить только вторую: первая прежняя. Скачать ZIP и импортировать в тестовую коллекцию; количество моделей, категории и связи тегов/фото верны.
- [ ] I03. Отрицательная цена, `vv:1:35`, пустое название и `2026-02-30` отклоняются с объяснениями возле полей. Если ошибки пришли из источника, строка отмечена и ZIP недоступен. После исправления предупреждения исчезают.
- [ ] I04. `2024-02-29` принимается; `2025-02-29` и `2026-09-31` отклоняются. Пустая дата/цена разрешены; после импорта дата переноса, 0 ₽ и пояснения. Заполненная неверная дата не заменяется автоматически.
- [ ] I05. Теги с новой строки: `Год выпуска: 1969`, `Premium`, `Красный, белый`, повтор `Premium`. После импорта три тега; запятая внутри последнего сохранена. Более 16 тегов или тег длиннее 100 символов отклоняются.
- [ ] I06. Поменять поля и нажать «Закрыть»/Escape: таблица прежняя. «Вернуть поля источника» восстанавливает черновик; таблица меняется только после применения. Ошибочные значения самого источника нужно исправить.
- [ ] I07. Подтвердить предпросмотр, затем применить правку: подтверждение и CAPTCHA сброшены. Смена валюты, столбцов, общей категории или масштаба также сбрасывает их. Исправленные поля имеют приоритет над новым соответствием столбцов.
- [ ] I08. Заполнить бренд/теги/категорию без исходных столбцов: они попадают в ZIP. При EUR исправленная цена считается в евро и пересчитывается по показанному курсу. Удалить URL фото: в ZIP заглушка, фото по ссылке не скачивается.
- [ ] I09. Новый источник или переключение файл/текст очищают исправления. После обновления страницы их нет. В volume/логах нет коллекции или исправлений (H15). Во время сборки нельзя менять параметры, файл или модель; после завершения/ошибки управление доступно.
- [ ] I10. На телефоне в обеих темах окно прокручивается целиком; с клавиатурой доступны нижние поля и кнопки. Фоновая страница под окном не прокручивается. На 320 px нет горизонтальной прокрутки. Текст `<b>модель</b>` отображается буквами, не как HTML.

- [ ] J01. Без входа раздел `/admin` закрыт; запрос `/api/admin/orders` без сессии возвращает 401. После входа пункт «Заказы» раскрывает раздел со списком. После выхода он снова недоступен, в том числе в старой вкладке.
- [ ] J02. «Создать черновик · 149 ₽» добавляет номер, сумму 149 ₽, статус «Ожидает оплаты», попыток 0. Не запрашивает файл, не вызывает ИИ и не списывает деньги. Во время создания остальные действия заблокированы; двойное быстрое нажатие создаёт один черновик.
- [ ] J03. Обновить страницу, затем перезапустить контейнер и снова войти. Полный номер черновика, сумма, статус и число попыток сохранены; задания ИИ из RAM после перезапуска исчезают.
- [ ] J04. Удалить тестовый неоплаченный несвязанный черновик: сообщение об удалении и обновлённый список. Связанный с платежом/оплаченный заказ этим методом удалить нельзя — эта защита проверена автоматически, кнопки «пометить оплаченным» нет.
- [ ] J05. В тестовом запросе из инструментов разработчика попытаться передать вместе с номером запроса `amountMinor`, `paymentState` или `source`: ответ 400, запись не меняется. Запрос изменения без `X-CSRF-Token` получает 403. Эти случаи также проверены автоматически; ключи/коллекции в тестовый запрос не вставлять.
- [ ] J06. В `orders.json` только служебные номера, хеш доступа, суммы, статусы и времена. Нет имён исходных файлов, моделей, фото, текстов, ответов ИИ и ZIP. Браузерный API списка не отдаёт хеши доступа и идентификаторы платежей.
- [ ] J07. По желанию создать 21 тестовый черновик, соблюдая лимит 6 созданий в минуту: появляются страницы по 20 записей. Удалить единственный черновик последней страницы — список возвращается к предыдущей. Такой объём не нужен для проверки ИИ и не расходует его лимиты.
- [ ] J08. В светлой/тёмной теме на ПК и ширине 320 px номер переносится по строкам, кнопки читаемы, горизонтальной прокрутки нет. На `/automatic` оплата и гостевая обработка остаются отключёнными. После пересборки проверить, что новые файлы попали в контейнер.

## K. Связь оплаченного заказа с очередью — вручную после открытия гостевого пути

Внутренний адаптер проверен `test/order-processing.test.js`, гостевая загрузка/запуск/статус/отмена добавлены в разделе O. Для реального ручного сценария нужны выдача кодов и платёжный сервис. **Сейчас пункты K не считать доступными действиями для обычного посетителя.** На втором ПК можно запустить общий комплект из 107 тестов по `SECOND_COMPUTER_SETUP.md`; старые проверки H–J остаются доступными. Детали — [ORDER_PROCESSING.md](ORDER_PROCESSING.md).

- [ ] K01. Неоплаченный заказ, неверный ключ доступа, отсутствие согласия или устаревшие участники не запускают ИИ. Чужой заказ не получает и не отменяет результат.
- [ ] K02. Двойной запрос с одним номером и исходником возвращает одно задание/попытку. Изменённый исходник или маршрут с этим номером отклоняются. Две одинаковые модели остаются двумя.
- [ ] K03. Переполненная очередь, неподдерживаемый/пустой/слишком большой источник и превышение 300 записей не расходуют попытку и не вызывают ИИ.
- [ ] K04. Отмена в очереди не отправляет задание ИИ. При отмене работающего запроса новый запуск запрещён до его фактической остановки и сохранения статуса; после этого новая попытка использует прежнюю оплату.
- [ ] K05. Неверный ответ ИИ или временная ошибка допускают новый номер попытки в пределах лимита. Повтор старого номера показывает прежнюю ошибку и не вызывает ИИ снова.
- [ ] K06. Через 10 минут результат недоступен, содержимое удалено, возможен повтор по тому же заказу. Распознавание само по себе не означает завершение платного переноса или получение ZIP.
- [ ] K07. После перезапуска статус оплаты сохранён, источник/результат исчезли. Старый номер запроса не создаёт новое задание; повторная загрузка с новым номером разрешена в рамках лимита.
- [ ] K08. На отдельном тестовом экземпляре отказ записи статуса закрывает повтор и выдачу неподтверждённого результата. После восстановления хранилища согласуются только служебные метаданные; коллекции и ответы ИИ не записываются и не попадают в сообщения ошибки.

## M. Оплаченный результат → проверка → ZIP — технический пилот

Методы проверены в `test/order-delivery.test.js`, HTTP — в `test/guest-transfer.test.js`; инструкция — [ORDER_DELIVERY.md](ORDER_DELIVERY.md). **Кнопки подключены к `/order`, но для ручных M/P нужен выданный код тестового оплаченного заказа. До оформления его нет.** Оплата вымышленная в тестах; коммерческие правила завершения/повторов требуют согласования.

- [ ] M01. Только код своего оплаченного заказа открывает его готовые модели и сверку строк. Неоплаченный заказ, чужой результат, ещё не готовое/потерянное задание не дают ZIP. В предпросмотре нет технической диагностики ключей или провайдеров.
- [ ] M02. Подтвердить сверку строк, проверить/исправить поля и замечания. Без этих подтверждений ZIP закрыт. Подмена списка моделей, исходных номеров, суммы или соответствия полей отклоняется. Неверные дата/цена/масштаб/теги выявляются до фото.
- [ ] M03. У двух одинаковых моделей исправить вторую. После ZIP и импорта первая прежняя, правки только у второй; категории, теги и связи фото целы. Серверный исходный результат не изменён правками.
- [ ] M04. Быстро дважды скачать один вариант: одна сборка. До срока повторное скачивание собирает ZIP без нового ИИ/оплаты/попытки. Для других правок нужен новый номер и подтверждение. Во время текущей сборки другой вариант отклоняется.
- [ ] M05. Для EUR показан актуальный курс/дата. При обновлении даты сервер требует новой проверки; недоступный ЦБ не даёт ZIP с неверной ценой. Оплата и готовые модели сохраняются до срока результата.
- [ ] M06. После сборки статус остаётся «готов к проверке». Только отдельное «ZIP сохранён» с квитанцией последнего варианта завершает заказ. Сначала убедиться, что файл действительно сохранён; после подтверждения сервер удаляет модели и больше не выдаёт этот ZIP. Повтор подтверждения не создаёт новую запись.
- [ ] M07. На отдельном тестовом экземпляре ошибка записи завершения даёт безопасный отказ; до срока можно повторить подтверждение, не оплачивая и не распознавая снова. Подтверждение не принимается без успешно собранного варианта.
- [ ] M08. Отмена/срок во время фото останавливают ZIP, не подменяют отмену заглушкой и не выдают частичный архив. Новая попытка закрыта до фактической остановки. Предпросмотр/скачивание не продлевают 10 минут хранения результата.
- [ ] M09. Подтверждение, принятое до срока, дожидается записи: одновременно нельзя отменить заказ или собрать другой ZIP. При перезапуске до подтверждения оплата сохранена, но результат/архив/квитанция потеряны; повтор требует исходник. Завершённый заказ остаётся завершённым.
- [ ] M10. После сборки/отмены/подтверждения в volume и логах нет источников, моделей, правок, фотографий, ZIP или квитанций. Допустимы только служебные метаданные заказа. Две темы и телефон дополнительно проверяются в P.

## N. Бесплатная сборка ZIP: общий лимит и остановка — можно проверять сейчас

Использовать тестовую коллекцию и настроенную CAPTCHA. Трудные случаи реального обрыва и срока уже покрыты `test/archive-capacity.test.js`; специально замедлять работу следует только на отдельном тестовом экземпляре.

- [ ] N01. Маленький CSV/XLSX/JSON/TXT и вставленный JSON скачиваются прежним способом. ZIP импортируется в DomCollection; фото, цены и исправленные поля верны. Обычные ошибки полей и CAPTCHA прежние.
- [ ] N02. Во время сборки обновить/закрыть вкладку. После остановки заново загрузить источник и скачать: места не остаются навечно занятыми, незавершённый архив не предлагается как готовый. Перезагрузка очищает локальные правки как и раньше.
- [ ] N03. Если одновременно выполняются две достаточно долгие тестовые сборки, третья получает понятное сообщение о занятости и паузу. После окончания одной можно повторить. Новый внутренний оплаченный путь использует тот же лимит — эта часть пока проверяется автоматически.
- [ ] N04. На отдельном замедленном тестовом экземпляре превышение двух минут останавливает сборку с понятной ошибкой; частичный ZIP не выдаётся. Место освобождается после выхода из текущей операции, затем доступен повтор. На обычном маленьком файле искусственно ждать две минуты не нужно.

- [ ] O09. Открыть готовые модели: видны все записи, девять полей, читаемые предупреждения и сверка всех исходных строк, включая строки без модели. Два одинаковых названия не объединяются; теги показываются обычным текстом.
- [ ] O10. Готовые модели можно исправить и скачать ZIP по сценарию P; один просмотр или скачивание не завершают заказ. Завершение требует отдельного подтверждения сохранения.
- [ ] O11. После десяти минут/отмены предпросмотр исчезает, исходник требуется снова. Перезапуск сохраняет оплату, но не коллекцию. При потере доступа старые модели убираются; чужой код не получает и не отменяет результат.
- [ ] O12. Две темы, ПК и 320 px: нет горизонтальной прокрутки, карточки раскрываются, кнопки/ошибки читаемы. В volume и логах нет кода, исходника/имени файла, моделей, текста, фото или диагностики ИИ. В браузере очистка/уход убирают источник и предпросмотр.

## P. Исправления, скачивание и завершение по заказу — технический пилот

Сценарии добавлены 02.10.2026, отметки оставлены пользователю. Нужны отдельный оплаченный тестовый заказ/выданный код и настроенная CAPTCHA. До подключения оформления выдачи кодов нет; нельзя использовать админ-код/хеш или менять рабочие платежи вручную. HTTP/отмену/квитанции покрывают автоматические тесты. Команда Docker — в [SECOND_COMPUTER_SETUP.md](SECOND_COMPUTER_SETUP.md). Реальные загрузки ZIP и импорт проверять в браузере второго ПК/телефона.

- [ ] P01. Открыть готовые модели → раскрыть карточку → «Изменить модель». Редактор показывает девять полей. На ПК, телефоне/320 px и в двух темах поля читаемы, редактор прокручивается, закрытие/отмена доступны; горизонтальной прокрутки нет.
- [ ] P02. Удалить название; попробовать масштаб `vv:1:35`, цену `-1`/`7,300`, дату `2026-02-30` и больше 16 тегов. Видны ошибки, сохранение закрыто до исправления. Пустые необязательные поля разрешены.
- [ ] P03. Изменить две одинаковые модели по отдельности. После сохранения правки только в выбранной позиции, карточка остаётся раскрытой с отметкой. Выйти через «Отмена»/Esc: несохранённые изменения исчезают. При правке только цены прежние теги сохраняются.
- [ ] P04. Подтвердить три проверки, затем изменить модель, валюту, дату или категорию. Подтверждения/CAPTCHA сбрасываются; ранее скачанный вариант нельзя подтвердить как новый. Обновление страницы удаляет локальные правки, результат в пределах срока можно открыть заново.
- [ ] P05. Выбрать дату/категорию/1:64 для пустых полей. Заполненные значения в ZIP сохраняются; масштаб подставляется только автомобилям. Пустая цена становится 0 ₽ с пояснением, дата переноса тоже поясняется в заметках.
- [ ] P06. Выбрать EUR: без проверки курса ZIP закрыт. «Проверить курс ЦБ» показывает сумму/дату; после проверки подтвердить модели заново. Изменившаяся дата курса требует обновления; при недоступности ЦБ готовые модели сохраняются до срока.
- [ ] P07. Без одного из трёх подтверждений или CAPTCHA скачивание закрыто. Во время сборки нельзя менять поля или начать второй запрос кнопкой. По завершении показано, что файл передан браузеру; заказ ещё готов к проверке.
- [ ] P08. Проверить загрузки: там `dom_collection_transfer.zip`. Импортировать его в тестовую DomCollection: цены/категории/теги/даты и правки второй одинаковой модели верны. У недоступных фото заглушка; сообщение перечисляет их исходные строки.
- [ ] P09. До срока повторить скачивание с новой CAPTCHA: нет нового ИИ-запроса, оплаты или попытки. Новый вариант после правок заменяет прежнюю квитанцию; кнопка завершения относится к последнему скачанному варианту.
- [ ] P10. При достаточно долгой сборке нажать «Отменить скачивание» или закрыть вкладку. Только скачивание останавливается; модели доступны до прежнего срока. Повтор возможен после фактической остановки без новой попытки ИИ. Отключение одной вкладки не срывает общий одинаковый запрос другой — дополнительно покрыто тестами.
- [ ] P11. После ZIP «Завершить заказ» закрыто до галочки о сохранении. Проверить файл в загрузках, подтвердить и завершить. Статус `Перенос завершён`, моделей/ZIP больше нет; повторное нажатие не создаёт второе завершение. Не завершать до сохранения архива.
- [ ] P12. После сетевого сбоя подтверждения сначала обновить состояние: оно могло сохраниться. Если заказ не завершён и срок ещё действует, повторить подтверждение. При новом открытии вкладки квитанция потеряна: ZIP нужно скачать заново, если результат ещё жив.
- [ ] P13. Дождаться десятиминутного срока с открытым редактором или готовой квитанцией: редактор закрывается, модели/правки/квитанция исчезают, завершение/ZIP недоступны. Просмотр и скачивание срок не продлевают.
- [ ] P14. «Очистить»/смена кода во время ZIP убирают данные и кнопку отмены текущего скачивания. Поздний ответ не возвращает их и не скачивает файл. Повторный вход в другой заказ не показывает правки/квитанцию прошлого.
- [ ] P15. После скачивания, остановки, срока и завершения в volume/логах нет моделей, исправлений, имени исходника, фото, ZIP, кода или квитанции. На устройстве пользователя сохранённый ZIP остаётся; это не серверное хранение.

## T. Переход на прямой API Groq (02.10.2026)

Раздел заменяет прежние проверки модели/квоты OpenRouter в R и S. При проверках других разделов используйте Groq, новую версию условий и фактические лимиты организации. Ниже отмечаются только реальные проверки пользователя на втором ПК.

- [ ] T01. Получить исходники и пересобрать контейнер по `GROQ_SETUP.md`. Прежний админ-код и `.env` продолжают работать; заказы и список ключей читаются после перезапуска.
- [ ] T02. Старые ключи показаны как ключи предыдущего провайдера, недоступны для включения/проверки и отсутствуют в выборе распознавания. Новый ключ с `gsk_` сохраняется через админку. Ключ с `sk-or-v1-`, `Bearer` или внутренним пробелом отклоняется.
- [ ] T03. Кнопка «Проверить» принимает действующий ключ и сообщает доступность `openai/gpt-oss-20b` в списке моделей. Не показывает выдуманный суточный остаток или тариф. Неверный/отозванный ключ отклоняется без раскрытия значения.
- [ ] T04. Новый запрос с 2–3 вымышленными моделями успешно распознаётся. Название, бренд, масштаб, цена и даты проверены; год выпуска попадает в тег. Пустые поля не выдумываются. Результат проходит предпросмотр и ZIP с заглушкой при отсутствии фото.
- [ ] T05. Небольшой CSV/XLSX/TXT проходит фоновое задание и сверку исходных строк. Все номера учтены, повторы не объединены, цены и валюта правильно доходят до предпросмотра. Ошибка не выдаёт частичный результат.
- [ ] T06. При естественном 429 показана пауза и безопасная диагностика; повтор внутри паузы не обращается к этому ключу. Не создавать нагрузку специально. Резервная отправка требует отдельного согласия и только согласованных владельцев; несколько ключей одной организации не увеличивают квоту.
