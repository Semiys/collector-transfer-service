# Архив: проверка ошибок OpenRouter

**Провайдер заменён на Groq 02.10.2026.** Инструкции ниже описывают предыдущую интеграцию. Текущая регистрация, подключение ключа и диагностика — [GROQ_SETUP.md](GROQ_SETUP.md). Ключ OpenRouter не отправляется в Groq; старые счётчики и правила поставщика больше не применяются.

Две строки таблицы обычно помещаются в одну часть запроса. HTTP 429 означает отказ из-за ограничения запросов: он может исходить от OpenRouter или поставщика выбранной модели. Небольшой файл и действительный ключ не гарантируют доступность бесплатной модели.

02.10.2026 модель по умолчанию заменена на [NVIDIA Nemotron 3 Super (free)](https://openrouter.ai/nvidia/nemotron-3-super-120b-a12b:free), идентификатор `nvidia/nemotron-3-super-120b-a12b:free`. В каталоге указаны нулевая цена входных/выходных токенов и поддержка JSON-схемы. Используется тот же ключ OpenRouter из админки; создавать ключ NVIDIA не нужно. После смены исходников нужно пересобрать и перезапустить контейнер, затем создать новое задание. Старое задание с ошибкой само не продолжится.

Это подтверждение свойств каталога, не успешного запроса на конкретном аккаунте. Ошибка поставщика на первой части может быть связана с его перегрузкой; смена ключа, ведущего к тому же поставщику, может ничего не изменить. По одному HTTP 429 нельзя заключить, что модель перестала быть бесплатной или отключена для всех пользователей. Замена модели не обнуляет ограничения аккаунта.

Бесплатный маршрут NVIDIA описан как пробный; вход и выход могут журналироваться у внешнего поставщика. Для закрытого пилота использовать тестовую коллекцию без персональных данных. Перед коммерческим запуском проверить условия поставщика и выбрать маршрут, разрешённый для платной услуги. Наш сервис по-прежнему не сохраняет содержимое коллекций; правила внешнего поставщика отражены в условиях обработки.

## На втором ПК

1. Получить новые исходники через GitHub Desktop. Остановить старый контейнер через `Ctrl+C` в окне запуска и пересобрать:

   ```powershell
   cd D:\Projects\collector-transfer-service
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-docker.ps1
   ```

2. Войти в админку, возле основного ключа нажать **«Проверить»**. Проверка обращается к метаданным ключа, без отправки коллекции и запроса генерации.
3. Прочитать «использовано / осталось / лимит» за текущий день UTC. Если OpenRouter не вернул счётчик, интерфейс явно пишет об этом, а не показывает придуманный остаток. Счётчик относится к аккаунту, не к одной таблице; ограничения за минуту и доступность поставщика в него не входят. Для освобождённых от этого ограничения аккаунтов/маршрутов суточный остаток не определяет возможность запроса.
4. Если остаток есть, после указанной паузы отправить маленький тестовый файл на две записи. При 429 прочитать сообщение задания:
   - **Лимит сервиса**: источник определён по заголовкам ограничения OpenRouter. Числа в сообщении относятся к сработавшему лимиту; это не обязательно суточный лимит.
   - **Поставщик модели**: API сообщил сведения об ошибке поставщика. Бесплатный маршрут может быть недоступен даже при оставшейся квоте аккаунта.
   - **Источник не указан**: ответ не позволяет надёжно отличить эти причины.
5. Если API указал `Retry-After`, сервис соблюдает эту паузу. Иначе применяется местная пауза пять минут с явной пометкой, что срок от API неизвестен. Пауза не гарантирует успех следующей попытки. Повторное нажатие во время паузы не делает новый запрос к этому ключу и показывает оставшееся время.
6. Для разбора прислать текст счётчика и сообщения ошибки. API-ключ и полный ответ с содержимым коллекции присылать не нужно.

Не создавать много запросов для проверки ограничения. Другие ключи не гарантируют устранения общего ограничения модели или поставщика. Резервные владельцы по-прежнему используются только с отдельным согласием на согласованный список. Автоматического бесконечного повтора нет; после неудачного задания нужно дождаться паузы и создать новое.

## Реализовано

- Счётчик бесплатных запросов из `GET /api/v1/key`, когда он предоставлен API.
- Безопасная категория источника 429 и срок ожидания без сохранения исходного сообщения/метаданных ошибки.
- Сохранение фактического остатка паузы, включая ситуацию, когда все согласованные ключи временно недоступны.
- Обработка 429 внутри JSON при HTTP 200: частичный результат не принимается.
- Проверка ключа ограничена 8 секундами и ответом 64 КБ; ошибка запроса генерации — ответом 64 КБ. Коллекция в этих диагностических данных не сохраняется.

Автоматические тесты используют подставные ответы API. Они проверяют наш код, но не подтверждают доступность реального запроса выбранной модели или остаток конкретного аккаунта.

Основание: [лимиты OpenRouter](https://openrouter.ai/docs/api_reference/limits), [ошибки и Retry-After](https://openrouter.ai/docs/api_reference/errors-and-debugging).

## Ошибка «некорректный JSON ответа» после CSV (02.10.2026)

У ответа два уровня: HTTP-тело OpenRouter с полем `choices`, затем текст модели в `choices[0].message.content`, содержащий JSON коллекции. Старое сообщение «OpenRouter вернул некорректный JSON ответа» относилось к первому уровню. Оно ошибочно появлялось также при таймауте и обрыве чтения. Само это сообщение не доказывало, что модель составила неправильную коллекцию.

Теперь диагностика различает:

- **Не завершил ответ за 60 секунд** — истёк общий срок получения ответа, в том числе после HTTP-заголовков.
- **Соединение оборвалось при чтении** — тело ответа не удалось получить целиком.
- **Пустой HTTP-ответ** — нечего разбирать; результат коллекции отсутствует.
- **Превышает лимит 2 МБ** — ответ остановлен по размеру.
- **Некорректный JSON в HTTP-ответе** — тело получено, но оболочка OpenRouter не читается как JSON. Указаны только HTTP-статус и число байтов ответа.
- **ИИ вернул результат не в формате JSON** — оболочка OpenRouter прочитана, отклонён уже текст модели. Полная Markdown-обёртка допускается; повреждённое содержимое не восстанавливается.

В документации OpenRouter описаны ошибки внутри HTTP 200, включая ошибки внутри `choices`. Такой ответ не принимается как успешный частичный перенос. Даже исправление формата внешним [Response Healing](https://openrouter.ai/docs/guides/features/plugins/response-healing) не гарантирует восстановления всех ответов, особенно оборванных по лимиту токенов.

После пересборки выполнить один повтор новым заданием с тем же ключом. Если снова ошибка, прислать полную строку «Часть 1» с уточнённой причиной. На этом ПК реального ключа нет, поэтому доступность API и точная причина прежнего отказа остаются непроверенными. Ответы коллекции и ключи в журналы не записывать.
