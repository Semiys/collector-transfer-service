# Перенос по оплаченному заказу

## Текущее состояние

02.10.2026 `/order` получил файл/текст, отдельные согласия, CAPTCHA, запуск, ход обработки, остановку и просмотр всех распознанных моделей со сверкой исходных строк. Код проверяется сервером; клиент не может пометить заказ оплаченным. Оформление, приём оплаты и выдача кодов ещё не подключены. Поэтому обычный посетитель пока не получает рабочий оплаченный заказ. Черновик администратора не открывает этот поток.

Это этап закрытого пилота. В `/order` теперь также доступны исправления девяти полей модели, настройки архива, сборка ZIP и отдельное подтверждение его сохранения. Кнопки оплаты нет. Внутренний адаптер описан в `ORDER_DELIVERY.md`; коммерческие правила повторов/завершения нужно согласовать до открытия продаж.

## Доступность

Для маршрутов нужны хранилище заказов, хранилище ключей и настроенная CAPTCHA. `/api/orders/config` сообщает эту техническую готовность как `processingAvailable`; `creationAvailable` и `paymentAvailable` остаются `false`. Ответ проверки статуса допускает обработку только для оплаченного заказа. Форма запуска дополнительно требует доступного участника ИИ и разрешённой попытки.

Без конфигурации запросы обработки получают 503. Неоплаченный/возвращённый заказ получает 402, неверный код — 404. Проверка статуса по коду доступна отдельно и не требует CAPTCHA. Реальная работоспособность ИИ и CAPTCHA должна быть проверена до открытия услуги.

## API

Все действия — POST под `/api/orders/transfer`. Полный код `CT1` передаётся **заголовком `X-Order-Code`**, а не URL. Это позволяет проверить оплату и владельца **до** загрузки файла в RAM. Существующая проверка `/api/orders/status` по-прежнему принимает код JSON-телом. Не логировать этот заголовок, тела запросов, ответы предпросмотра и имена файлов; в production нужны HTTPS и соответствующая настройка прокси/APM.

- `/conditions`: JSON `{}`. Возвращает версию условий, ревизию маршрута, `aiConfigured` и `fallbackAvailable`. Имена владельцев, идентификаторы аккаунтов, названия ключей и ключи не выдаются.
- `/state`: JSON `{}`. Только служебные статусы своего заказа/заданий, сроки и числовой прогресс. Сообщения работника с техническими сведениями заменены безопасной общей ошибкой.
- `/start`: multipart с одним `file` либо `text`. Поля: `policyVersion`, `routeRevision`, `consentToAI`, `acceptProcessing`, `consentToAccountSwitch`, `captchaToken`. Булевы значения строго `true`/`false` строками. `Idempotency-Key` — UUID v4. Принимается только подтверждённая оплата; участники выбираются сервером из актуального согласия. CAPTCHA проверяется для действия `collection_recognize`. Ответ 202 содержит номер/статус задания без содержимого коллекции.
- `/cancel`: JSON `{ "jobId": "UUID" }`. Остановка своей обработки или удаление своего готового результата. Повторная попытка запрещена до фактического выхода работника и сохранения состояния заказа.
- `/preview`: JSON `{ "jobId": "UUID" }`. Только свой готовый результат: поля всех моделей, предупреждения, соответствие полей и сверка исходных строк. Нет ключей и диагностики поставщика. Клиент не передаёт замену моделей или оплату.
- `/build`: JSON до 540 КБ: `jobId`, `confirmedAudit: true`, `confirmedModels: true`, `options`, `edits`, `captchaToken`; заголовок `Idempotency-Key` — UUID v4. `options`: `priceCurrency` RUB/EUR, `defaultCategory`, `defaultScale`, `transferDate` ГГГГ-ММ-ДД, `acceptTextWarnings: true`, для EUR — `expectedRateDate` ДД.ММ.ГГГГ из проверенного курса ЦБ. `edits`: до 300 объектов `{rowIndex, values}` и 512 КБ; разрешены только девять полей существующих моделей. CAPTCHA проверяется для `collection_order_zip`. Ответ — ZIP с фиксированным именем, заголовками `X-Order-Receipt`, `X-Result-Expires-At`, `X-Photo-Failed-Rows`. Квитанция не содержит коллекцию и существует только в RAM.
- `/confirm-saved`: JSON `{jobId, receipt, downloadSaved: true}`; квитанция — 64 шестнадцатеричных символа из последнего успешного варианта ZIP. Завершает только свой оплаченный заказ и удаляет серверный результат. Повтор подтверждения идемпотентен, пока квитанция доступна. После сетевого сбоя проверять статус; это декларация пользователя о сохранении, а не доказательство загрузки браузером.

Неизвестные поля, query-параметры и неподдерживаемые действия отвергаются. Публичных create/pay/mark-paid методов нет. Гостевой код не даёт доступ в админку.

## Ограничения и повторы

- До 8 МБ, один CSV/XLSX/JSON/TXT; имя до 200 символов. Multipart: максимум семь текстовых полей, ограниченный размер каждого поля, два одновременно принимаемых запуска.
- До 200 000 символов текста, 300 непустых исходных строк, 8 000 символов в строке, 30 частей — общие проверки очереди перед расходом попытки.
- На IP: до 6 запусков, 60 чтений условий/статуса, 12 действий отмены/предпросмотра/подтверждения и 8 сборок ZIP в минуту; не более двух одновременных чтений и двух запросов загрузки/скачивания. Все пути сборки делят два рабочих места и срок две минуты. Занятость/лимит возвращают `Retry-After`. Это не полноценная защита от распределённой атаки; глобальную входящую нагрузку ограничивает инфраструктура.
- Один номер запроса с тем же исходником/маршрутом возвращает прежнее задание. Изменённый исходник с тем же номером отклоняется. Каждый повтор HTTP всё равно проверяет текущие согласия и новую CAPTCHA; второй ИИ-запуск не создаётся.
- После сетевого сбоя интерфейс сначала обновляет статус. Он не повторяет ИИ автоматически. Номер неопределённого запроса остаётся в RAM вкладки до смены исходника/согласий; обновление вкладки требует кода снова.
- Обработка ограничена 15 минутами, готовый результат — 10 минутами. По истечении срока/отмене ссылки очищаются, место удерживается до выхода операции. Перезапуск сохраняет только служебный заказ, без исходника и результата.

## Страница

При действующем задании форма загрузки скрыта; вместо неё ход работы, срок, ручное обновление и остановка. Состояние обновляется примерно раз в пять секунд в видимой вкладке. Скрытая вкладка не планирует новые проверки; возвращение обновляет статус. После временного сбоя повторяется только статус, не распознавание.

Готовый результат показывает все модели в раскрываемых карточках, предупреждения и сверку строк; текст вставляется через `textContent`. «Изменить модель» открывает редактор с проверками даты, цены, масштаба, тегов и длины полей. Две одинаковые модели исправляются отдельно по позиции. Правки не заменяют серверный исходный список. Изменение полей/настроек сбрасывает подтверждения, CAPTCHA, номер скачивания и квитанцию старого варианта.

Перед ZIP пользователь выбирает валюту, дату переноса для пустых дат, категорию и масштаб для пустых полей. Для EUR нужно проверить курс ЦБ. Три подтверждения сверки/полей/замечаний и отдельная CAPTCHA обязательны. Повторное скачивание того же варианта до срока результата не вызывает ИИ и не расходует попытку. Новые правки создают новый номер варианта; подтверждается только последняя успешная квитанция.

«Отменить скачивание», уход или очистка кода прерывают текущий HTTP-запрос. Если одинаковую сборку ждёт ещё одна вкладка, она продолжится для неё; после отключения всех ожидающих сборка получает сигнал остановки. Рабочее место удерживается до её фактического выхода. Распознанные модели остаются до прежнего срока, заказ не завершается. Это отличается от «Удалить результат».

Получение ZIP не завершает заказ. Браузеру передаётся файл; пользователь проверяет загрузки и отдельно подтверждает сохранение кнопкой «Завершить заказ». После этого модели удалены, скачивание закрыто. Квитанция, правки и временная ссылка браузера не записываются в storage или на серверный диск. Истечение срока очищает даже открытый редактор/скачивание; просмотры и скачивания не продлевают срок. Обновление вкладки теряет правки и квитанцию: при живом результате можно открыть модели и скачать заново.

В основной форме нет Groq, аккаунтов, имён владельцев или схемы ключей. Условия обработки доступны по ссылке в шапке и возле обязательного согласия. Необязательное согласие на повторную передачу остаётся отдельным и не отмечено заранее; изменение маршрута требует нового подтверждения.

Смена исходника сбрасывает согласия и CAPTCHA. «Очистить», обновление и уход со страницы очищают код, источник и предпросмотр в браузере. **Они не останавливают серверное задание**: для этого отдельная кнопка. Если вкладка потеряна, задание очищается по своему сроку; до этого повтор по коду восстанавливает состояние. Скрипты не записывают коллекцию/код в browser storage, cookies или журналы.
