## Назначение

«Хаб Коллекционера» — отдельный веб-сервис для переноса коллекций в локальное мобильное приложение DomCollection. Сервис развивается как курсовой проект по дисциплине «Методы и средства проектирования информационных систем». Мобильное приложение и сервис хранятся в разных репозиториях.

## Что реализовано в исходниках 0.1.0

1. Загрузка CSV, XLSX, JSON и структурированного TXT через веб-страницу с обработкой в оперативной памяти, без записи пользовательских файлов на диск; можно вставить текстовый список. Telegram-список с разделами и маркерами `•` разбирается локально без ИИ.
2. Предложение соответствия столбцов полям DomCollection и предварительный просмотр первых строк. Пользователь может изменить соответствие.
3. Пересчёт покупной цены из EUR в RUB по официальному курсу Банка России на дату курса, возвращённую его API. Исходная сумма и курс записываются в заметки модели.
4. Загрузка личных фото Hunt64 из `My Photo URL` и преобразование WebP/PNG/JPG в JPEG. Если фото отсутствует или недоступно, добавляется заглушка с пометкой.
5. Создание ZIP с `collection.json` и фото по формату, который принимает текущий DomCollection. Сервис заполняет `tags` и `modelTags`: сохраняет теги из исходного CSV/JSON и извлекает из структурированного TXT год выпуска, MOC/Loose, Premium и явно указанные тестовые образцы. Для строк категории «Автомобили» пользователь может выбрать масштаб 1:64 по умолчанию; аксессуарам масштаб не подставляется.
6. Админ-панель для учёта API-ключей согласившихся владельцев: вход по коду из локальных настроек, серверная сессия, выход и защита изменений, шифрование ключей на диске, проверка ключа через официальный API OpenRouter, включение/выключение и удаление. Через выбранный ключ можно распознать свободный текст бесплатной моделью `qwen/qwen3.8-27b:free`, просмотреть результат и передать его в обычный конвертер ZIP. Для каждого пробного запроса можно отдельно разрешить переключение на ключи до двух других владельцев при ограничении частоты или приближении к локальному порогу. Учёт попыток хранится в памяти сервера и не показывает точный лимит OpenRouter.

Если даты покупки нет, используется дата переноса с явной пометкой в заметках. `Date Added` из Hunt64 не считается датой покупки. Пустая покупная цена становится 0 ₽ с пометкой; оценочная стоимость из Hunt64 не используется как цена покупки.

Пользователь уточнил: файлы и содержимое коллекций не сохранять в сервисе. Текущая загрузка использует `multer.memoryStorage()`, фотографии и ZIP собираются в памяти и архив отдаётся в ответе. Это правило сохраняется и для будущего автоматического пути: не записывать исходники, фотографии, распознанные данные и ZIP на диск, в БД, журналы или резервные копии. Будущим заданиям нужны ограничения памяти и времени ожидания; после перезапуска посетитель повторно загружает исходник. Для восстановления оплаченного заказа можно отдельно сохранять идентификатор и состояние оплаты без содержимого коллекции. Правила внешнего ИИ-провайдера оговариваются отдельно.

Бесплатный ручной путь описан на странице `/guide`: пользователь сам обращается к DeepSeek, затем вставляет JSON на главной странице и получает ZIP. Автоматическое распознавание OpenRouter пока доступно только администратору, требует API-ключа и не проверялось с реальным ответом после закрепления Qwen. Фото с произвольных сайтов и входные ZIP не поддерживаются. Платежи не подключены. Цена 149 ₽ за автоматическую конвертацию — текущая гипотеза; перенос 5000 моделей за раз пока не реализован. Для защиты памяти небольшого сервера действуют лимиты: 8 МБ входного файла, 300 моделей, 100 МБ ZIP; для одного запроса OpenRouter — 20 000 символов и 100 моделей. План публичного развития описан в `PUBLIC_SERVICE_ROADMAP.md`.
