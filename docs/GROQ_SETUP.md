# Groq: регистрация, подключение и первая проверка

Переход подготовлен 02.10.2026. Сервис обращается напрямую к Groq API; модель пилота — `openai/gpt-oss-20b`. Она поддерживает строгую JSON-схему. Ключ добавляется через закрытую админку; отдельно устанавливать SDK или редактировать curl не нужно. Локальные тесты используют подставные ответы: доступность и качество реального API нужно проверить своим ключом.

## 1. Зарегистрировать аккаунт

1. Откройте [Groq Console](https://console.groq.com).
2. Если аккаунта нет, выберите регистрацию (**Sign Up**); если есть — вход (**Log In**). Используйте предложенный способ входа. При регистрации по почте подтвердите её, если сервис запросит подтверждение.
3. Завершите первоначальную настройку аккаунта/организации, если она появляется.
4. Для первой проверки используйте **Free**. Платный тариф **Developer** включать не требуется. Подписка на чат другого сервиса для Groq API не нужна.
5. Откройте [Data Controls](https://console.groq.com/settings/data-controls). Для выбранной организации включите **Zero Data Retention** для обычного распознавания, если он ещё выключен. Это настройка хранения входа/ответа у Groq; метаданные использования остаются. Возможность ZDR описана в [официальных правилах обработки данных](https://console.groq.com/docs/your-data). Не используйте Batch Processing или Fine-tuning: наш сервис их не вызывает.

Названия экранов могут меняться. Нужен аккаунт именно **Groq** (`groq.com`), не чат Grok.

## 2. Создать API-ключ

1. Откройте [API Keys](https://console.groq.com/keys).
2. Нажмите **Create API Key**.
3. Задайте понятное имя, например `collector-transfer-service`. Если есть выбор срока действия, выберите подходящий для тестирования срок и запомните его.
4. Подтвердите создание и скопируйте **весь ключ**. Ожидаемый формат начинается с `gsk_`.
5. Сохраните его у себя. В форму сервиса вставляется только значение ключа: без `Bearer`, кавычек и заголовков curl. Префикс `gsk_` должен быть один, уже внутри скопированного значения.

Ключ OpenRouter с `sk-or-v1-` не подходит. Не присылайте API-ключ в чат, скриншоты, Git или текст отчёта. При потере/раскрытии ключа отзовите его в Groq Console и создайте новый.

Создание ключа не требует выбирать модель внутри самого ключа. В нашем коде уже задана `openai/gpt-oss-20b`, без суффикса `:free`. Если модель ограничена настройками организации/проекта, проверьте **Model Permissions**.

## 3. Обновить сервис на втором ПК

Сначала закоммитьте и отправьте подготовленные исходники с первого ПК, затем получите их через **Fetch origin → Pull origin** в GitHub Desktop второго ПК. Если Pull недоступен, убедитесь, что открыт нужный репозиторий и ветка.

1. Откройте Docker Desktop в Windows 11 виртуальной машины и дождитесь готовности.
2. Остановите старый контейнер: `Ctrl+C` в терминале его запуска. Убедитесь, что прежний контейнер не занимает порт 8080.
3. Откройте PowerShell в папке репозитория и выполните:

   ```powershell
   Set-Location 'D:\Projects\collector-transfer-service'
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-docker.ps1
   ```

   Если репозиторий на втором ПК находится в другой папке, замените путь в первой строке.

4. Дождитесь сборки. Терминал покажет адрес сайта и **админ-код**; оставьте его открытым, пока проверяете сайт.
5. Откройте `http://localhost:8080/admin` **в браузере этой же виртуальной машины**.

Скрипт сам создаёт `.env` при первом запуске. Существующий `.env` оставьте: прежний `OPENROUTER_KEY_ENC_KEY` поддерживается как ключ шифрования, даже когда API уже Groq. При новом запуске создаётся нейтральное имя `AI_KEY_ENC_KEY`. Это не API-ключ, не адрес провайдера и не модель.

Не удаляйте `.env` или Docker-том `collector-transfer-data` для смены провайдера: они нужны для админ-кода, шифрования ключей и служебных заказов. Если переименовываете переменную шифрования, значение должно остаться прежним. Коллекции и фотографии в этом томе не сохраняются.

На Linux/macOS запуск из каталога репозитория: `sh ./scripts/start-docker.sh`. Используются Linux-контейнеры; локальные инструкции второго ПК рассчитаны на Docker Desktop, а не на установку Node в Windows.

## 4. Добавить ключ в нашу админку

1. Введите **админ-код из терминала** на странице входа. Это отдельный код, не `gsk_…`.
2. В панели откройте раздел **«Ключи распознавания · Groq»**.
3. Заполните **«Имя владельца»**, например своим именем, и **«Название ключа»**, например `Мой Groq`.
4. В **«API-ключ Groq»** вставьте скопированное значение целиком.
5. Подтвердите согласие владельца и нажмите **«Сохранить ключ»**.
6. У добавленного ключа нажмите **«Проверить»**.

Проверка делает авторизованный запрос списка моделей. Успех означает: Groq принял ключ, а выбранная модель есть в списке. Это **не** проверка генерации, тарифа или оставшейся квоты. Ключ хранится зашифрованным; в списке видны последние четыре символа. После перезапуска контейнера добавлять его заново не нужно.

Старые ключи OpenRouter показываются с пояснением и недоступны для включения, проверки и распознавания. Сервис не отправит их в Groq. При желании удалите их кнопкой **«Удалить»**; для работы достаточно нового ключа Groq.

## 5. Проверить настоящее распознавание

Сначала используйте небольшой вымышленный список без персональных данных. В разделе **«Быстрая проверка короткого текста»** выберите новый ключ и вставьте, например:

```text
Hot Wheels — Classic Bird, масштаб 1:64, цена покупки 250 рублей, куплено 2026-09-20, год выпуска модели 2020.
Matchbox — City Car, масштаб 1:64, цена покупки 180 рублей, куплено 2026-09-21.
```

Нажмите **«Распознать текст»**, проверьте две модели и нажмите **«Проверить модели и подготовить ZIP»**. На предпросмотре проверьте название, бренд, категорию, масштаб, цену/валюту, даты и теги. При отсутствии фото должна появиться заглушка. Сборка ZIP требует действующей настройки CAPTCHA, как раньше.

Затем проверьте ваш небольшой CSV через **«Перенести файл с помощью ИИ»**:

1. Выберите ключ и один файл; поле вставленного текста оставьте пустым.
2. Подтвердите передачу ИИ. Для первого запроса резервные ключи не нужны.
3. Нажмите **«Создать задание»**, дождитесь результата.
4. Проверьте сверку: каждая исходная строка относится к модели или объяснённому пропуску/заголовку. Частичный результат при ошибке не выдаётся.
5. Подтвердите сверку, перейдите к моделям, затем скачайте ZIP и проверьте импорт в мобильное приложение.

Не начинайте проверку с большой коллекции. Локальные ограничения пилота остаются: до 8 МБ файла, 300 исходных строк, 200 000 символов на задание, части до 15 строк/9000 символов. Они не гарантируют, что любой такой запрос впишется в лимиты Groq или 4096 токенов ответа. После ошибки создайте новое задание; старое само не возобновляется. Оплата и публичный запуск платного переноса пока не подключены.

## 6. Бесплатный тариф и ошибки

На дату проверки базовые лимиты Free для `openai/gpt-oss-20b`: **30 запросов в минуту, 1000 в сутки, 8000 токенов в минуту, 200 000 в сутки**. Ориентируйтесь на фактические значения своей организации в Console. Лимиты общие для организации, включая запросы вне нашего сервиса. Они не равны количеству моделей: одна коллекция может требовать нескольких запросов. [Официальные лимиты](https://console.groq.com/docs/rate-limits).

| Что произошло | Что делать |
| --- | --- |
| Ключ не сохраняется | Вставить полный ключ Groq с `gsk_`, без `Bearer`, кавычек и внутренних пробелов; ключ OpenRouter не подходит. |
| HTTP 401/403, ключ отклонён | Проверить копирование, срок действия, отзыв ключа и права организации/проекта. |
| Ключ принят, модель отсутствует | Проверить Model Permissions и доступность `openai/gpt-oss-20b` в Console. |
| HTTP 429 | Дождаться указанной паузы; проверить лимиты запросов и токенов. При отсутствии `Retry-After` наш сервис приостанавливает повтор на пять минут. Не нажимать отправку многократно. |
| HTTP 413 | Уменьшить файл или вставленный текст: запрос слишком велик для текущего ограничения. |
| Ответ оборвался по длине | Проверить меньший список; длинные заметки и подробные записи занимают много токенов. |
| Ошибка JSON/таймаут/соединение | Прислать точное безопасное сообщение из «Часть 1», без исходного ответа API и ключа. Строгая схема не исправляет обрыв HTTP. |
| ZIP не создаётся после распознавания | Проверить замечания/поля, валюту и CAPTCHA. Это отдельный этап после ИИ. |

Бесплатный тариф не даёт гарантии постоянной доступности. Дополнительные ключи той же организации не увеличивают её квоту. Резервные ключи других согласившихся владельцев используются только после фактического 429 и отдельного согласия для запроса/задания; переключение не гарантирует успеха. У каждого владельца отдельно проверяются настройки хранения и условия использования.
